# API: Resource & Endpoint Workflow

> Read this when adding or modifying API resources or oRPC endpoints.

Stack: **Hono** + **oRPC** (RPCHandler + OpenAPIHandler) + **Drizzle ORM** (Postgres) + **better-auth** + `@ship/db` `DbService<T>` wrappers.

---

## Resource Structure

Every resource lives in [`apps/api/src/resources/<name>/`](../apps/api/src/resources/):

```
<name>/
├── <name>.schema.ts       # Drizzle pgTable + Zod schemas
├── endpoints/             # One file per oRPC endpoint (filesystem-routed)
│   ├── list.ts
│   ├── create.ts
│   ├── [paramId]/
│   │   ├── get.ts
│   │   ├── update.ts
│   │   └── delete.ts
│   └── nested-group/      # Non-param subdirs = nested router groups (camelCased)
│       └── action.post.ts
├── methods/               # Optional: shared business logic (not routed)
└── handlers/              # Optional: event-bus side-effect handlers
    └── on-insert.ts       # subscribes to `<table>.insert`, `<table>.update`, `<table>.delete`
```

No `index.ts` barrels needed — codegen discovers endpoints from the filesystem.

## Filesystem Routing Conventions

The router + contract are auto-generated by [`scripts/codegen-router.ts`](../apps/api/scripts/codegen-router.ts) (watched in dev; runs on save).

**File naming → HTTP method:**
| Filename | Method | Path segment |
|----------|--------|-------------|
| `list.ts` | GET | (none — collection root) |
| `create.ts` | POST | (none) |
| `get.ts` | GET | (none) |
| `update.ts` | PUT | (none) |
| `delete.ts` | DELETE | (none) |
| `name.get.ts` | GET | `/name` |
| `name.post.ts` | POST | `/name` |

**Directories:**
- `[param]/` → `{param}` dynamic segment in URL
- `non-param-dir/` → nested router group (camelCased key)

## Endpoint Builder & Middlewares

The base builder is [`src/endpoint.ts`](../apps/api/src/endpoint.ts) — `import endpoint from '@/endpoint'`. It is the oRPC base builder with all global middlewares (currently a request logger) applied automatically via the registry at [`src/middlewares/global/`](../apps/api/src/middlewares/global/) (`index.ts` exports the array, `logger.ts` is the logger). Logging is global, so a public endpoint is just `endpoint.input(...)` with no gate.

**Gates** are default-export middlewares in [`src/middlewares/`](../apps/api/src/middlewares/), applied right after the base with `.use()`:

| Gate | Import | Effect |
|---|---|---|
| `isAuthorized` | `@/middlewares/is-authorized` | Adds `context.user` (`User`); throws `UNAUTHORIZED` if missing. |
| `isAdmin` | `@/middlewares/is-admin` | `isAuthorized` + checks `context.user.isAdmin`; throws otherwise. |

**Ownership / existence** uses two generic factories in `src/middlewares/`:

| Factory | Signature | Effect |
|---|---|---|
| `shouldExist(ctxKey, load, message?)` | `load` is `({ input, context }) => Promise<T \| null>` | Loads the entity into `context[ctxKey]`, throws `NOT_FOUND` if absent. |
| `shouldOwn(ctxKey, dbService, { idKey?, owner?, message? })` | sugar over `shouldExist` for the owned-by-id case | Resolves the id as `input[idKey] ?? input.id` (`idKey` defaults to `${ctxKey}Id`), matches `owner` (defaults to `'userId'`) against `context.user.id`, soft-delete aware; `NOT_FOUND` on mismatch (no existence leak). |

Per resource, create `resources/<r>/middlewares/should-own-<x>.ts` that default-exports a configured `shouldOwn(...)`, and apply it with `.use(shouldOwnX)` **after** `.input(...)` (it reads the validated input). The handler then reads the loaded entity from `context.<ctxKey>`.

`ORPCError` comes from `@orpc/server`: `import { ORPCError } from '@orpc/server'`.

## Endpoint Template

```typescript
import { z } from 'zod';

import db from '@/db';
import endpoint from '@/endpoint';
import isAuthorized from '@/middlewares/is-authorized';
import { publicSchema } from '@/resources/users/users.schema';

export default endpoint
  .use(isAuthorized)
  .input(z.object({ userId: z.string() }))
  .output(publicSchema)
  .handler(async ({ input, context }) => {
    return db.users.findFirst({ where: { id: input.userId, deletedAt: null } });
  });
```

With a per-resource ownership middleware, apply it after `.input(...)` and read the loaded entity from context:

```typescript
import endpoint from '@/endpoint';
import isAuthorized from '@/middlewares/is-authorized';
import shouldOwnPost from '@/resources/posts/middlewares/should-own-post';
import { idSchema, publicSchema } from '@/resources/posts/posts.schema';

export default endpoint
  .use(isAuthorized)
  .input(idSchema)
  .use(shouldOwnPost)
  .output(publicSchema)
  .handler(async ({ context }) => {
    // context.post is loaded and owned by context.user
    return context.post;
  });
```

## Database (`@ship/db` DbService)

`db.<table>` exposes a typed `DbService<T>`:

```typescript
import db from '@/db';

// Read
const user = await db.users.findFirst({ where: { id, deletedAt: null } });
const users = await db.users.find({ where: { isAdmin: true }, orderBy: { createdAt: 'desc' } });
const total = await db.users.count({ where: { deletedAt: null } });
const page  = await db.users.findPage({ where, orderBy, page: 1, perPage: 20 });

// Write
const created = await db.users.insertOne({ email, fullName });
await db.users.insertMany([...]);
const updated = await db.users.updateOne({ id }, { isAdmin: true });
```

**Filter operators:** `{ field: value }` for equality, `{ field: { gt, gte, lt, lte, in, notIn, like, ilike, isNull, isNotNull } }`, `OR: [...]`, `AND: [...]`.

**Soft delete:** `baseColumns.deletedAt` is `null` for live rows. Every read should include `deletedAt: null` in the filter when applicable.

**Relation loading:** passing `with`/`columns` to `findFirst`/`find`/`findPage` transparently delegates to Drizzle's relational query builder (requires a `src/relations.ts`). When a `relations.ts` exists, the generated service type carries a relations generic — `DbService<typeof table, typeof rawDb.query.table>`; otherwise it is `DbService<typeof table>`. `codegen-db.ts` emits the correct form automatically.

### Transactions

`db.transaction()` returns the same typed `DBType` so nested calls stay strongly typed:

```typescript
await db.transaction(async (tx) => {
  const user = await tx.users.insertOne({ email, fullName });
  await tx.accounts.insertOne({ userId: user.id, providerId: 'email' });
});
```

### Event-Bus Hooks

Any resource with a `handlers/` directory auto-wires its `DbService` to emit mutation events on the typed event bus (see [`src/event-bus.ts`](../apps/api/src/event-bus.ts)):

```typescript
// resources/users/handlers/sync-analytics.ts
import { eventBus } from '@/event-bus';

eventBus.on('users.insert', (data) => {
  for (const user of data.docs) {
    // data.docs is typed Select<users>[]; data.prevDocs available on update/delete
  }
});
```

Event keys are `<tableName>.{insert,update,delete}`. Handlers run after the write commits.

## Shared Schema Helpers

From [`src/resources/base.schema.ts`](../apps/api/src/resources/base.schema.ts):

- `baseColumns` — `id` (uuid), `createdAt`, `updatedAt`, `deletedAt` (soft delete).
- `paginationSchema` — Zod schema with `page`, `perPage`, `searchValue`, `sort`. Spread into endpoint inputs.
- `listResultSchema(itemSchema)` — Zod wrapper around `{ results, pagesCount, count }`. Spread into endpoint outputs.

## Add New Resource Checklist

- [ ] Create `resources/<name>/<name>.schema.ts` (pgTable + Zod schemas).
- [ ] Run `pnpm codegen` — regenerates `src/db.ts` (DbService wrappers) + `src/router.ts` (oRPC router) + `src/contract.ts`.
- [ ] Add `resources/<name>/endpoints/*.ts`.
- [ ] Optionally add `resources/<name>/handlers/*.ts` for mutation side effects.
- [ ] Generate migration: `pnpm generate` → creates a drizzle migration file. Commit it.
- [ ] Apply: `pnpm migrate` (or rely on the migrator service on next deploy).
- [ ] Rebuild API types for web consumers: `pnpm build:types`.
- [ ] `pnpm tsc --noEmit` in both `apps/api` and `apps/web`.

## Constants Sharing

Shared enums/constants between API and web live in [`packages/app-constants`](../packages/app-constants). Use `z.enum(USER_STATUSES)` rather than inlining string literals.

## Update Triggers

Update this doc when:
- Codegen script behavior changes (`scripts/codegen-router.ts`, `scripts/codegen-db.ts`).
- A new gate or middleware added in `src/middlewares/`.
- A new always-on middleware added to `src/middlewares/global/`.
- A per-resource ownership middleware (`shouldOwn`/`shouldExist`) added or changed.
- `DbService` API or transaction shape changes.
- Event-bus key format changes.
